# Issue tracker

GitHub is the repository's issue tracker when durable ticketing is needed.

- Do not create an issue merely to begin a repository change.
- Use the current approved conversation or specification as the requirements
  source when the work fits in one development session.
- Present specifications and ticket sets for approval before creating them.
- Use native issue dependencies for blocking relationships when available, and
  link implementation tickets to their parent specification.
- Apply the configured ready-for-agent label only after publication approval.
- Close an implementation ticket through `Closes #N` when the completing pull
  request merges. Close a parent specification only when that pull request
  completes the entire specification.
- Creating an issue, publishing a specification, applying a label, or posting
  an issue comment requires explicit user approval.
- Query the current issue list before referring to existing tickets. Existing
  pull requests or issues do not authorize creating or posting to a ticket.
