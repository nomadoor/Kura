# AI-Toolkit 0.13.30 to 0.13.32: upstream delta and Kura impact

The inventory the `backend-upgrade-audit` skill asks for. Upstream commits are
named by SHA; upstream has no Git tags, so versions come from `version.py`.

## Identities

| | Old | New |

| Upstream version | 0.13.30 | 0.13.32 |

The upstream Dockerfile clones `main` at build time and the image config
records no commit. The new commit was read from the built Kura image
(`/opt/kura-runtime.json`, `ai_toolkit_commit`, written by `git rev-parse HEAD`)
and from `git log -1` in the upstream image; both give `9d408eb`, the commit
that sets VERSION 0.13.32. `scripts/extract_ai_toolkit_baseline.py` refuses
any other commit.

Python packages and CUDA are unchanged (torch 2.13.0+cu130, torchvision
0.28.0+cu130, diffusers 0.39.0.dev0, transformers 5.5.3, accelerate 1.15.0,
CUDA 13.0): 25 of the 27 upstream amd64 layers are byte-identical to 0.13.30;
only the source clone and the UI build differ.

## Upstream delta (`dcebc74..9d408eb`, 4 commits)

| Commit | Files | Kind | Content |
| --- | --- | --- | --- |
| `82e6311` | `diffusion_models/ui.tsx`, `toolkit/models/registry.py`, `testing/test_model_loading.py` | new UI entry of an existing arch | `moss_image:edit`: SFT weights (`OpenMOSS-Team/MOSS-Image-SFT`) with `model_kwargs {edit, kv_cache, match_target_res, uncond_skip_layers: [22]}`. `toolkit/models/registry.py` is the inference engine's registry, not the training one. |
| `9a1828f` (0.13.31) | `moss_image/moss_image.py` | save format, existing model | MOSS LoRA `.proj.qkv.` keys are saved as separate `.proj.q/k/v.` keys (up rows split, down and alpha copied); loading fuses them back. LoKr stays fused. Applies to every MOSS mode and to the Resume weights. |
| `88360c6` | `moss_image/src/transformer.py` | training compute path | MOSS edit with `kv_cache` and no padded key runs reference isolation as two unmasked SDPA calls instead of one masked call. |
| `9d408eb` (0.13.32) | `flux3/flux3.py` | reference contract, existing model | `use_raw_control_images = True` keeps references unresized for `_fit_reference`, and a stacked `(B, N, C, H, W)` control is unpacked into N references, so FLUX.3 reads every reference of a sample. |

Commits after `9d408eb` on upstream main (`577004a` convrot libdevice fix,
`7b94dc5` UI notes, `8cf43dd` text encoder parked on CPU after caching text
embeddings) are not in the 0.13.32 image, and Kura does not backport them.

No architecture is added or removed: the trained arch set (`LEGACY_ARCHS` and
`get_all_models()`) is the same 60 archs, and all 49 model classes import in
the new image (`2026-10-18-ai-toolkit-0.13.32-class-import.yaml`). Neither
`jobConfig.ts`, `config_modules.py`, `data_loader.py`, nor
`BaseSDTrainProcess.py` changed, so Kura's cited line numbers and both Kura
patches (`0001-save-by-completed-updates.patch`, the MiniMax-H3 finite-gradient
patch) apply unchanged in substance.
